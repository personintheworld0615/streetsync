# StreetSync Design Context & Rules

## Design Context

### Users
- **The Commuter / Transit User**: Needs a fast, low-interaction interface to report road hazards and transit issues while moving. They rely on voice-activated reporting.
- **The Neighborhood Advocate**: Active citizens, pedestrians, and cyclists who report localized issues (e.g., ADA accessibility issues, illegal dumping). They want a tactile, map-centric, highly visual reporting tool.
- **Municipal Administrators**: City government staff who manage, triage, and resolve incoming tickets using the dashboard.

### Brand Personality
- **Friendly & Community-First**: Built for neighborhoods and real people. Empathy and warmth are key.
- **Fast & Responsive**: Every interaction removes barriers. Focus on instant response and voice/telemetry ease.
- **Trust-Based & Comforting**: Designed to evoke confidence that the city is listening and working.
- **Three-Word Brand Voice**: **Friendly, Community, Fast**

### Aesthetic Direction
- **Visual Tone**: Warm Minimalist / Clean Public Utility. A bright, approachable, highly tactile look using soft borders and human touch elements.
- **Palette**: Clean white (`#FFFFFF`) base, warm soft whites/off-white (`oklch(0.98 0.003 70)`) for surfaces, comforting warm blue (`oklch(0.55 0.14 245)`) as primary accent, soft green (`oklch(0.65 0.14 140)`) for resolved items, and clean charcoal/dark slate (`oklch(0.25 0.01 240)`) for typography. Avoid dark mode and heavy gradients.
- **Typography**: Display: *Space Grotesk*. Body: *Geist*.
- **Theme**: Pure light mode, warm and clean.

## 🚫 Custom Project Design Rules

### 1. No Pill Buttons
- BANNED: Fully rounded buttons (`rounded-full`), inputs, or pill-shaped tabs.
- REWRITE: Use sharp corners (`rounded-none`) or minimal border-radius (`rounded-xs` or `rounded-md`). Buttons should feel structural and tactile, not bubbly.

### 2. No Code Symbols in Copy (`//`, `/*`, etc.)
- BANNED: Using developer shorthand or programming symbols in public-facing UI copy (e.g., prefixing headers with `//` or writing states like `// DISPATCHED`).
- REWRITE: Use clean typography, size hierarchy, weight shifts, uppercase letter-spacing, or simple descriptive icons.

### 3. Core Visual Restrictions (From Impeccable & Taste)
- **No Side-Stripe Accent Borders**: Never use thick side borders (`border-l-4`, etc.) on cards or alerts. Use full thin borders, subtle background fills, or prefix markers instead.
- **No "AI Purple" or Heavy Neon Gradients**: Palettes must remain solid and organic. Rely on comforting, stable colors.
- **No Pure Black (#000) or Pure White (#FFF) for text**: Use perceptually uniform warm dark slates (`oklch(0.20 0.01 240)`) on soft warm off-white bases (`oklch(0.99 0.003 70)`).
- **No `h-screen`**: Use `min-h-[100dvh]` to prevent viewport jumping on mobile devices.

### 4. Interactive UX Rules (From UI-UX Pro Max)
- **Touch Target Limits**: Minimum target size of `44x44px` on all interactive buttons/selectors, with at least an `8px` gap between siblings.
- **Form Labels**: Ensure every interactive input has a visible, associated text label (never rely on placeholders alone).
- **Tab Layouts**: Breakpoints must scale mobile-first and prevent horizontal page overflow.

### 5. Animation Quality Rules (From Emil Design Eng)
- **UI Interaction Speed**: Keep micro-interactions under `300ms` (ideally `150ms-250ms`).
- **Correct Easing**: Use `ease-out` for entry/interaction transitions. Never use `ease-in` for UI animations, as it delays the initial motion.
- **Physical Feedback**: All primary buttons must scale down on press to provide physical feel:
  ```css
  button:active {
    transform: scale(0.97);
  }
  ```
